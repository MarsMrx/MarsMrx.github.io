实验：手工编写一个简单的PE文件

实验任务

  • 利用010Editor、WinHex等工具直接键入十六进制，保存为exe文件
  • PE文件弹出“Hi，姓名“，姓名为个人学生姓名

实验环境

  • Windows 7
  • Windows XP

实验要求

  • 思路清晰，有条理有步骤，形成md文档，并导出pdf文件
  • 严禁直接抄袭和拷贝大模型生成的内容

实验内容/步骤

一、关于PE文件

👉 PE文件（Portable Executable，便携式可执行文件）是 Windows 操作系统 中用于可执行程序、动态链接库（DLL）、驱动程序等的一种文件格式。它是 Windows 平台上最常见的二进制文件格式之一。

（一）PE文件的主要特点

1. 跨平台兼容性
尽管名为“便携式”，PE 文件主要用于 Windows 系统，但它的设计允许在不同架构的 Windows 系统上运行（如 x86、x64）。

2. 文件结构

  • PE 文件具有标准化的结构，通常包括以下部分：

    • DOS 头：用于兼容旧的 DOS 系统。

    • NT头（PE头）：包括NT头、文件头、选项头。包含文件的基本信息，如入口点、代码段和数据段的位置。

    • 节表（Section Table）：描述文件中各个节（如代码、数据、资源等）的位置和属性。

    • 节数据：实际存储代码、数据、资源等内容的部分。

3.常见类型

  • .exe：可执行程序。

  • .dll：动态链接库。

  • .sys：驱动程序。

  • .ocx：ActiveX 控件。

（二）PE文件的加载过程

  1. 操作系统读取 PE 文件的头部信息。
  2. 根据节表将代码、数据等加载到内存中。
  3. 解析导入表（Import Table）以加载所需的动态链接库。
  4. 跳转到入口点（Entry Point）开始执行程序。

二、编写PE文件

实现目标 🚩：利用winhex实现手写196Byte大小的PE文件（又名：畸形/变形PE），要求MessageBox弹框显示“Hi,姓名”

1. 创建文件

使用winhex，新建196字节大小的PE文件并将数据区全初始化为CC

2.编写DOS_HEADER部分

Offset Content Description
0x00 0x5A4D 文件头标识
0x3C 0x00000004 指向NT头’PE’标识的地址

3.编写NT头的Signature部分

Offset Content Description
0x04 0x00004550 ‘PE00’NT头标识

4.编写NT头的FileHeader部分

Offset Content Description
0x08 0x104C 指定程序的运行平台（0x104C为intel 386（x86 32））
0x0A 0x0001 PE中的节数量
0x18 0x0080 选项头大小
0x1A 0x010F 文件属性

5.编写NT头的OPTIONAL_HEADER部分

Offset Content Description
0x1C 0x010B PE标志字即程序位数(32位系统)
0x2C 0x00000000 程序执行入口RVA
0x38 0x00400000 内存加载基址(exe默认)
0x40 0x00000004 文件对齐值（最小限值）
0x4C 0x0004 主子系统版本号
0X4E 0x0000 副子系统版本号
0X50 0x00000000 版本号
0X54 0x00001000 PE文件在进程内存中的总大小
0X58 0x000000C4 PE文件头部在文件中的总大小
0X60 0x0002 程序类型，2是图形界面
0x62 0x0000 文件特性，默认是0
0x64 0x07FFFFFF 初始化时保留的栈大小
0x68 0x07FFFFFF 初始化时实际提交的栈大小
0x6C 0x07FFFFFF 初始化时保留的堆大小
0x70 0x07FFFFFF 初始化时实际提交的堆大小
0x78 0x00000004 数据目录的元素个数
0x7C 0x00000000 4项元素的数据目录

6.编写节表部分

Offset Content Description
0xA4 0x000000C4 内存时机占用大小
0xA8 0x00000000 内存地址RVA
0xAC 0x000000C4 文件大小
0xB0 0x00000000 文件偏移
0xC4 0xE00000E0 节属性

7.基础PE总览

8.编写导入内容：库和函数

  • 实现弹框需要写入：1.库名（user32）和2.函数名（MessageBoxA）,根据两个字符串的长度（+00结束符）找到最合适的位置并写入

    Offset Content Description
    0x30 7Byte dll名：”user32”
    0x0C 12Byte 函数名”MessageBoxA”

9.编写导入表项

  • 导入表IMAGE_IMPORT_DESCRIPTOR 置于0xB0处，因为PE加载后，0xB0-0xC3处内存会被初始化为全0

    Offset Content Description
    0xBC 0x00000030 RVA指向dll名
    0xC0 0x0000009C RVA指向IAT表

10.编写IAT表 IMAGE_THUNK_DATA32

Offset Content Description
0x9C 0x0000000A 指向IMAGE_IMPORT_BY_NAME
0xA0 0x00000000 以全0作为结尾项

11.将导入表位置写入数据目录中

  • offset 0x80;0x000000B0;导入表位置

12.编写汇编指令：获取MessageBoxA函数地址并传参调用

Offset Content Description
0x60 “Hi,MarsMrx” 在选项头的堆栈空间值区编写弹框文本
0x1F 0x6A00 参数4：对话框按钮类型
0x21 0x6A00 参数3：消息框标题
0x23 0x6864004000 参数2：消息框内容
0x25 0x6A00 参数1：窗口句柄
0x2A 0xEB18 短跳至空闲区以备调用函数
0x44 0xFF159C004000 从IAT表中获取API地址并调用
0x4A 0xC3 调用后返回

对写入的内容 Hi,MarsMrx进行16进制编码，然后填入对应位置

13.修改OEP

  • OEP:原本的程序入口点（实际为偏移，+模块基址=实际入口点）
  • 文件偏移0x44，OEP：FF15 9C004000= CALL 0040009C
