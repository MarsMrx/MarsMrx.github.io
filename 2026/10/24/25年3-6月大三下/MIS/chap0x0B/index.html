实验十：IoTGoat 网络服务安全与协议模糊测试

实验任务

  • IoTGoat 安全分析 —— Insecure Network Services
  • 模糊测试(Fuzzing)

实验环境

  • kali
  • boofuzz
  • ghidra

实验内容

实验一：IoTGoat 安全分析 —— Insecure Network Services

步骤一：扫描TCP端口

使用nmap扫描已知的iotgoat的IP，查看其端口的状态

步骤二：SSH 22端口

根据扫描结果发现其22端口是开放的，结合上节课破解的用户名和密码；尝试ssh远程登录

步骤三：dnsmasq 53端口

端口53一般是DNS服务，扫描53端口发现，正在使用dnsmasq2.7.3服务，经过搜索发现，该版本的服务存在相关的漏洞，比如DNS中毒、DoS攻击，缓冲区堆溢出等等

步骤四：backdoor 5515 端口

根据namp扫描结果中的端口，尝试netcat连接这些端口，其中5515端口连接成功，根据信息收集，此端口是一个用于提供root shell的后门，便于为开发人员测试和提供服务

进一步探究后门是如何提供，去检查./etc/init.d文件夹(❗在提取出来的固件的目录下，是./etc/不是/etc)，发现有一个shellback的文件，指向./usr/bin/shellback

检查./usr/bin/shellback这个文件，发现它是一个二进制文件可执行文件，作用是为每次IoTGoat系统启动时加载的后门提供服务

(扩展)步骤四：ghidra分析/usr/bin/shellback

目标➡️：使用Ghidra分析这个二进制文件，尝试定位到提供后门服务的函数

1.新建项目用于分析shellback,导入文件，并点击进行分析

2.分析后

  • 在symbol Tree,里可以看到有main函数了等

  • 看字符串界面，发现有一些比如socket、listen、bind等等，有个最明显的080486ec [***]Successfully Connected to IoTGoat's Backdoor[***]

3.直接查找刚才那个字符串的reference，发现它位于主函数中

4.一看主函数，非常明显的bind shell特征；进一步分析函数定位提供后门服务的代码

步骤五：telnetd 65534 端口

netcat连接最后一个开放端口65534，发现是个类似ssh的可以登录的服务

nmap扫描该端口，发现该端口是telnet服务，由于telnet协议是明文形式，it is a bad idea😮‍💨

实验二：模糊测试(Fuzzing)-使用boofuzz

模糊测试（Fuzz Testing 或简称 Fuzzing）是一种软件测试技术，其核心在于通
过自动化方式注入错误或畸形数据来发现实现层面的漏洞。

模糊测试器实现:模糊测试器是一种自动向程序/堆栈注入半随机数据并检测漏洞的程序。

  • 数据生成依赖于生成器，而漏洞识别则依靠调试工具。
  • 生成器通常结合使用静态模糊向量（已知危险值）和完全随机数据
  • 新一代模糊测试器采用遗传算法关联注入数据与观察到的影响，此类工具目前尚未公开。

安装boofuzz协议模糊测试器

完成 Simple FTP

1.准备ftp server

  • 克隆仓库：Simple ftp server

此时ftp server已经成功开启，监听在8201端口

2.修改ftp_simple.py中修改监听端口为8021，然后运行

运行./ftp的终端界面会显示结果，在浏览器访问http://localhost:26000/也可以看到测试的信息

发现在测试到8837用例时，ftp服务器崩溃了。在测试用例8836中，发送给STOR命令256byte的....AAAA\r\n后，到测试8837用例时，发送USER命令时，显示目标连接重置，之后无法重新连接，确实在ftp server端也显示客户端断连，无法创建子进程

推测可能是8836测试时，STOR命令的模糊测试的输入可能触发了缓冲区溢出或者非法内存访问，也可能是服务拒绝，结果导致服务中断崩溃
