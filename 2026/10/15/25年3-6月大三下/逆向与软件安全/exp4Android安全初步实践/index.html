二、本地使用ADB功能

adb(android debug bridge) 安卓调试桥
ADB，即 Android Debug Bridge，是一种功能多样的命令行工具，它是一个客户端 - 服务器端程序，充当调试桥的角色。客户端通常是用于操作的电脑，而服务端则是 Android 设备。同时，ADB 也是 Android SDK 中的一个实用工具，可对 Android 模拟器或真实的 Android 设备进行直接操作和管理，adb 命令可用于执行各种设备操作，例如安装和调试应用。

确保本地adb可用，并且已经成功与设备建立连接。连接成功后我们就可以利用adb对设备进行操控，比如可以通过adb shell input text "MarsMrx"对刚才的程序进行输入用户名和密码

1.构造带有恶意payload的APK文件

由于msf生成的安卓木马过于老旧,在安装时会出现版本不兼容问题(踩坑)，所以需要重新反编译apk文件然后进行修改sdk版本，然后进行签名，因为一般Android的移动设备不允许安装没有适当签名证书的应用程序

  • 修改AndroidManifest.xml文件，增加android:exported="true"属性

  • 修改apktopl.yml,更改sdkinfo中的版本，以及添加不强制压缩

  • 重新打包apk

  • 对齐并签名

虽然有成功连接，但是会发现msf不太稳定，连接会不久就断开，可能需要更高级的提权以及通过其他方式建立持久化后门

问题与解决

  1. As of Android 12, android:exported must be set; use true to make the activity available to other apps, and false otherwise. For launcher activities, this should be set to true.

    解决：
    从 Android 12（API 31）开始，所有带有 <intent-filter> 的组件（如 Activity、Service、Receiver）必须显式声明 android:exported 属性，否则编译会报错。

    所以MainActivity 是带有 <intent-filter> 的 launcher Activity，必须加上 android:exported=”true”

  2. 从kali把文件传到window上，想办法使得安卓模拟设备去安装这个apk，尝试通过abd install backdoor.apk发现拒绝

    • 问题：msf生成的apk文件的sdk版本太老，但是手机要求至少是24

    • 解决：通过参数强制允许安装，虽然显示安装成功。以为成功了，结果去模拟器上一看不兼容，这个方法不行

    原因：Android 11（API 30）及以上版本 的新限制导致的，要求 APK 中的 resources.arsc 文件必须满足以下条件：
    未压缩存储（不能使用 ZIP 压缩）和4字节对齐（内存对齐优化）

    解决：本问题以及问题2见上述第三部分利用msf逆向远程控制安卓设备

  3. 关于msf生成的apk,因为版本老旧问题，无法在安卓模拟设备上安装的问题,原因是msf生成的apk文件时要求目标sdk是17，但是Android studio的sdk对应的api是36

    • 也许可以通过下载Android studio的sdk的较低版本，从而解决这个问题
