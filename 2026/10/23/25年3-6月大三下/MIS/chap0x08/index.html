实验一：复现 CVE-2022-30024

A buffer overflow in the httpd daemon on TP-Link TL-WR841N V12 (firmware version 3.16.9) devices allows an authenticated remote attacker to execute arbitrary code via a GET request to the page for the System Tools of the Wi-Fi network. This affects TL-WR841 V12 TL-WR841N(EU)_V12_160624 and TL-WR841 V11 TL-WR841N(EU)_V11_160325 , TL-WR841N_V11_150616 and TL-WR841 V10 TL-WR841N_V10_150310 are also affected.

TP-Link TL-WR841N V12 3.16.9 固件中的httpd守护进程中存缓冲区溢出漏洞，允许经过验证的远程攻击者通过wifi网络的系统设置的界面以GET请求的方式执行任意代码。

(扩展)缓冲区溢出之栈溢出

栈溢出漏洞原理：栈溢出指的是程序向栈中某个变量中写入的字节数超过了这个变量本身所申请的字节数，
因而导致与其相邻的栈中的变量的值被改变。

栈溢出的基本前提：1.程序必须向栈上写入数据；2.写入的数据大小未被良好控制

栈溢出程序利用
最典型的栈溢出利用是覆盖程序的返回地址为攻击者所控制的地址

1. 对.c文件进行编译

查看是否开启了pie保护，如果含有--enable-default-pie参数则代表 PIE 默认已开启，需要在编译指令中添加参数-no-pie。

看到gets()不会检查输入字符串的长度，是以回车来判断输入是否结束，所以易于导致栈溢出

2.checksec工具检查编译出文件的安全属性

  • Partial RELRO：启用部分重定位只读保护

  • STACK CANARY：没有开启canary保活

  • NX(No eXecute):NX 位已启用，这意味着数据段（如栈和堆）上的代码不能被执行

  • PIE:No PIE

3.关闭ASLR

ASLR（Address Space Layout Randomization）是Linux系统提供的一种安全机制，它通过随机分配进程的地址空间来提高安全性。当ASLR被启用时，进程的地址空间会在启动时随机分配，从而打乱基址

value description
0 关闭ASLR
1 普通的 ASLR。栈基地址、mmap 基地址、.so 加载基地址都将被随机化，但是堆基地址没有随机化
2 增强的 ASLR，在 1 的基础上，增加了堆基地址随机化

➡️修改echo 0 >/proc/sys/kernel/randomize_va_space来关闭ASLR

  2. gcc编译stack_demo.c文件时，出现错误

  • 在64位系统上编译32位程序时缺少必要的32位库文件

  • 安装sudo apt install gcc-multilib后重新编译
