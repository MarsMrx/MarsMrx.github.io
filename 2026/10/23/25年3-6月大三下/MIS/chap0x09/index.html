实验环境

  • kali
  • ghidra工具

实验内容

问题一：如何定位该漏洞在固件中影响到的组件？

步骤一：查找并收集CVE漏洞信息

1.CVE漏洞信息

  • CVE-2022-30024 Detail

    A buffer overflow in the httpd daemon on TP-Link TL-WR841N V12 (firmware version 3.16.9) devices allows an authenticated remote attacker to execute arbitrary code via a GET request to the page for the System Tools of the Wi-Fi network. This affects TL-WR841 V12 TL-WR841N(EU)_V12_160624 and TL-WR841 V11 TL-WR841N(EU)_V11_160325 , TL-WR841N_V11_150616 and TL-WR841 V10 TL-WR841N_V10_150310 are also affected.

    这是一个基于栈的缓冲区溢出，存在于二进制程序httpd（提供web服务）的ipAddrDispose函数中。漏洞发生在将 GET 请求的参数值分配给栈变量的过程中，该过程允许用户向栈内存中输入大量数据，而这些数据攻击者可控。

2.查看漏洞分析报告

  • 1day to 0day(CVE-2022-30024) on TP-Link TL-WR841N

发现

  • 参数从PingIframeRpm接口传递
  • 溢出参数位置是ping_addr
  • 影响ipAddrDispose函数

步骤二：定位受影响组件

  1. 定位httpd组件

    • 使用binwalk解压固件

    • 进入解压后的目录文件夹进行查找httpd组件

  2. 搜索PingIfraeRpm接口

  3. 搜索ping_addr接口

  4. 搜索ipAddrDispose函数

问题⼆：如何查找在 httpd 组件中，查找PingIframeRpm、ping_addr、ipAddrDispose 等信息？

步骤一：使用Ghidra分析httpd

Ghidra是⼀个软件逆向⼯程 （SRE） 框架,包含一套功能齐全的软件分析工具，支持多种平台上分析编译代码，功能包括反汇编、反编译、图形化和脚本编写等；支持多种处理器指令集和可执行格式

1.安装Ghidra

我的kali里面不幸并没有自带Ghidra，手动安装

2. 使用ghidra分析httpd

  • 创建Ghidra工程项目

  • 把解压出来的固件目录文件夹下的usr/bin/httpd文件拖入到刚创建的项目中

  • 双击httpd程序，进入Ghidra分析界面，点击Analyze，开始分析

步骤二：在 Ghidra 中 查找 PingIframeRpm/ping_addr关键词

(一) 在 Defined Strings 搜索框中输⼊ PingIframeRpm，即可搜索到该字符串

发现PingIframeRpm字符串在地址00546ea0处定义，右键对应变量，点击References，即可查看该字符串被引用的函数。然后逐一进入对应函数进行分析

可以看到共有3个函数使用了这个变量

1. 分析 httpPingIframeInit()

这个初始化函数，调用httpRpmConfAdd为/userRpm/PingIframeRpm.htm这个url注册一个HTTP路由，并将函数FUN_0044a530作为处理这个url的函数

2.分析函数 FUN_0044a530()

在这个函数中，会通过httpGenEnv来获取ping_addr,doType,isNew的值，然后通过调用ipAddrDispose函数传递ping_addr，漏洞就是在这里

(二) 在 Defined Strings 中搜索ping_addr

发现ping_addr在00546ef8处定义

查找引用该变量的函数，发现是FUN_0044a530，上述已分析过

步骤三：在 Ghidra 中 查找 ipAddrDispose 关键词

1.在 Defined Strings 搜索框中输⼊ ipAddrDispose，即可搜索到该字符串

发现 ipAddrDispose 字符串在 00412404 地址处定义

2. 在 Functions 搜索框中输⼊ ipAddrDispose，即可搜索到该函数

发现 ipAddrDispose 字符串在 0046d000 地址处定义

3. 点击 Decomplie: ipAddrDispose 页⾯，查看 Ghidra 对于 ipAddrDispose 的反编译代码

问题三：如何在 Ghidra 中，分析缺陷函数代码逻辑？

问题在于ipAddrDispose并未对ping_addr的长度进行限制，虽然有计算其长度，但是这个长度就是我们输入的ping_addr值的长度。而代码里是将ping_addr值写入到了一个大小定义为52字节的缓冲区，所以很容易出现缓冲区溢出
